# Дела в порядке — MVP

Веб-приложение для управления проектами и задачами: создание проектов и задач, сроки,
статусы, поиск и фильтры, прогресс и просроченные задачи. Интерфейс на русском языке,
светлый минималистичный адаптивный дизайн.

Данные хранятся в `localStorage` браузера — это демонстрационный MVP без сервера.

> Оформление (шрифты Open Sans, фоновое изображение, логотип, иконки полей ввода,
> палитра, кнопки и модальные окна) взято из папки-шаблона `init-20261021T074935Z-1-001/`
> и адаптировано под адаптивную вёрстку. Файлы шаблона не изменялись, их копии
> лежат в `src/assets/`.

## Стек

- React 19 + TypeScript + Vite 6
- Обычный CSS (без CSS-фреймворков) по макету init: шрифт Open Sans, фиолетовый акцент
  `#6e45e2`, рамки `#d7dbe8`, скругления 3 px, фон-фото и логотип из макета;
  иконки интерфейса — lucide-react
- Хранение — `localStorage`
- Тесты — Vitest, линтинг — ESLint (typescript-eslint, react-hooks)

## Структура

```
src/
  types.ts               # типы Project, Task, статусы, параметры запроса
  assets/                # шрифты Open Sans, логотип, фон и иконки из макета init
  lib/logic.ts           # просроченность, прогресс, поиск/фильтры/сортировка, completedAt
  lib/storage.ts         # безопасное чтение/запись localStorage
  lib/reducer.ts         # редьюсер CRUD + стартовое состояние (демо/пусто/восстановление)
  lib/demo.ts            # демонстрационный набор данных
  store/                 # контекст состояния и уведомлений
  components/            # модальные окна, подтверждения, формы, бейджи, пустые состояния
  pages/                 # Обзор, Проекты, Все задачи, Карточка задачи
  App.tsx                # навигация, оркестрация модальных окон
  styles.css             # все стили, включая адаптивные правила
```

## Реализованные функции

- **Обзор**: счётчики всех задач, «К выполнению», «В работе», «Выполнена», «Просрочена»;
  ближайшие дедлайны; список просроченных; прогресс по каждому проекту; быстрые действия
  (создать задачу, создать проект, показать просроченные); баннер удаления демо-данных.
- **Проекты**: список с прогрессом и количеством задач, создание, редактирование,
  переход к задачам проекта, удаление с подтверждением и предупреждением о связанных задачах;
  при удалении проекта удаляются и его задачи (осиротевших записей не остаётся).
- **Все задачи**: поиск по названию и описанию, фильтры по проекту/статусу/сроку
  (просроченные, сегодня, ближайшие 7 дней, без срока), сортировка по дедлайну
  (↑/↓) и по названию, сброс фильтров, счётчик найденных задач, быстрая смена статуса
  из списка, пустые состояния («нет задач», «ничего не найдено»).
- **Карточка задачи**: все поля, смена статуса в один клик, редактирование, удаление
  с подтверждением, отметка просроченности, даты создания/обновления/завершения.
- **Бизнес-логика**: статусы «К выполнению» / «В работе» / «Выполнена»;
  при переводе в «Выполнена» фиксируется `completedAt`, при возврате — сбрасывается;
  просроченная задача = незавершённая с `dueDate` раньше сегодняшней даты;
  прогресс проекта = выполненные / всего × 100% (0% для проекта без задач).
- **Валидация и UX**: обязательное название задачи и проекта, сообщения об ошибках,
  подтверждения удаления, всплывающие уведомления, состояния пустых списков,
  закрытие модалок клавишей `Escape`, ловушка фокуса, подпись для скринридеров,
  видимый фокус с клавиатуры.
- **Данные**: автосохранение в `localStorage`, восстановление после перезагрузки;
  некорректные сохранённые данные не приводят к падению: битые записи отбрасываются,
  задачи-сироты удаляются, при нечитаемом хранилище приложение стартует с пустого списка;
  демо-набор можно удалить одной кнопкой.

## Известные ограничения

- Данные хранятся только в `localStorage` браузера: без сервера, синхронизации между
  устройствами, совместной работы, резервного копирования и защиты на сервере.
- Одно приложение — один пользователь, без авторизации и уведомлений (по ТЗ).
- Список маршрутов управляется состоянием приложения: прямых ссылок на отдельный экран
  и кнопки «назад» браузера нет.
- Демо-данные помечены префиксом id `demo-`; задачи, созданные внутри демо-проектов,
  удаляются вместе с ними.
- `localStorage` ограничён квотой браузера (обычно ~5 МБ) — при переполнении изменения
  останутся только до перезагрузки страницы.

### Статический хостинг

Сборка уже использует относительные пути (`base: './'`), поэтому любой хостинг,
раздающий содержимое `dist/`, подойдёт:

```bash
npm run build
# затем загрузите содержимое dist/ на хостинг
```

- **GitHub Pages**: включите Pages для ветки `gh-pages` (или папки `docs`) и разместите
  там содержимое `dist/`. Например, локально: `npm run build && npx gh-pages -d dist`.
  Либо настройте GitHub Actions со сборкой `npm ci && npm run build` и публикацией
  артефакта `dist/` (стандартный workflow `actions/deploy-pages`).
- **Netlify / Vercel**: build command `npm run build`, publish directory `dist`.
- После деплоя откройте сайт по HTTPS — данные `localStorage` привязаны к домену
  и порту, поэтому на новом домене пользователь начнёт с демо-набора.
